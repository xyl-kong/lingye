# 项目工作约束

本文件适用于整个 `tablet-workspace` 仓库。它与用户当次明确指令冲突时，以用户最新指令为准。

## 当前阶段

- 2026-10-30 用户已确认按审计问题持续改进；当前实施按 Feature ID 和 `IMPLEMENTATION_PLAN.md` 逐项推进。
- 每次修改只处理有明确证据和验收标准的问题；禁止无证据的大范围重写。
- 当前版本为 0.15、页面格式 22；任何后续格式变更仍需迁移、回滚和备份证明。
- 不得移动项目或既有文件；不得删除用户页面、图片、备份、构建产物或测试数据。
- 审计文档不是实施授权。

## 证据规则

- 不得仅凭文件、类名、按钮或 README 判断功能完成。
- `VERIFIED` 必须有当前构建下的实际测试证据。
- 单元测试可证明纯数据逻辑；UI、Android 生命周期和输入必须另有设备/模拟器证据。
- 不得把 Mock、占位、空事件、静态 UI 标为完成。
- 不得将 `PARTIAL` 或 `UNVERIFIED` 汇总为完成。
- 发现的缺陷必须记录复现步骤、构建版本、设备/OS 和证据路径。

## AFFiNE 参考

- 优先依据实际产品、锁定 commit 源码，其次才是官网宣传。
- 参考基线见 `docs/affine-audit/REFERENCE_BASELINE.md`。
- 不绕过 Cloudflare、验证码、权限或登录保护。
- 无法核实的内容写入 `UNVERIFIED_ITEMS.md`。
- AFFiNE Android 是 Capacitor/WebView + BlockSuite；本仓库是原生 Compose 自研模型，不得把相似 UI 当作同构实现。

## 修改前要求

- 先阅读相关矩阵条目、源码、测试和现有设计文档。
- 任何页面格式、数据库格式或共享块格式变化，必须先设计迁移、回滚和备份验证。
- 架构边界变更先写 ADR 或计划，不得直接在 `MainActivity.kt` 继续堆叠。
- 改动已有用户文件前先检查 Git/文件状态；环境无法检查时说明限制，不假设干净工作树。
- 不得改写或覆盖用户已有 `AGENTS.md`；若未来出现同名文件，先提出非破坏性合并方案。

## Android 与平板要求

- 优先保证触摸、键盘、手写笔和系统返回行为。
- 系统 Back 必须按导航层级工作，不能默认退出应用。
- 任何画布交互必须验证选择、命中、视觉状态、取消和保存。
- 新 UI 至少检查横屏/竖屏、分屏、150%/200% 字体和中文/英文。
- 手写笔压感、掌托、延迟不能只用模拟器证明。
- 页面 I/O 不得在没有基准的情况下放在 Compose 热路径。

## 数据安全

- 使用 `AtomicFile` 或同等原子替换。
- 破坏性操作必须确认并保留恢复路径。
- 备份必须拒绝 ZIP Traversal、重复条目、超大条目和缺失资产。
- 不允许为了测试删除真实用户数据；使用独立测试副本或明确标注的测试页面。
- 不得把密钥、令牌、个人信息或用户页面内容写入审计文档或提交。

## 完成标准

- 实施后更新对应 Feature ID 状态和证据。
- 主流程、失败路径和旧格式迁移都要验证。
- 代码存在、构建成功或单个 happy path 通过都不足以声明完成。
- 只有 `docs/affine-audit/ACCEPTANCE_CRITERIA.md` 的条件满足时，才能使用 `VERIFIED`。
- 未全部 `VERIFIED` 或经批准 `NOT_APPLICABLE` 时，不得声称“已完全对齐 AFFiNE”。
