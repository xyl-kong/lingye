# 文本工具拖拽区域创建（2026-11-02）

用户反馈：点击文本工具后，文本框出现在固定位置（400,180），不能自由选择区域。

## 1. 原问题

- 底部文本工具只打开文本参数栏，并把工具切到“选择”。
- 参数栏里的“正文 / H / 代码 / 引用 / 项目符号 / 编号 / 待办”直接调用 `addTextBox(400f, 180f, ...)` 或 `addCanvasTextBlock(..., 400f, 180f, ...)`，因此总是出现在固定坐标。

## 2. 现在的行为

- 点击底部 T 文本工具后，工具变为 `文本`，文本参数栏保持显示。
- 参数栏中的“正文 / H1–H6 / 代码 / 引用 / 项目符号 / 编号 / 待办”改为选择**待创建类型**，不再立即插入固定位置的文本。
- 在画布上拖拽出一个区域，松手后按该区域创建文本框：
  - 位置取拖拽起点/终点的左上角；
  - 宽高取拖拽区域，最小 120×56；
  - 正文使用当前默认字体大小、颜色和对齐；
  - 标题/代码/引用/列表/待办使用对应块类型与样式。
- 创建后自动切回选择工具并选中新文本框，可直接拖动或双击编辑。
- 再次点击 T 会退出文本工具；在其他工具激活时，文本工具不会残留。
- 首次点击即显示参数栏：原先 `LaunchedEffect(tool)` 在工具不是“选择/移动”时会强制关闭 `textToolsMenu`，导致第一次点击先打开又立刻关闭；现在允许 `tool == "文本"` 保留参数栏。

## 3. 代码

- `MainActivity.kt`
  - 底部 T 按钮与快捷键 T：`setTool("文本")`，再次点击 `chooseTool("选择")`。
  - `pendingTextKind` 状态：正文为 `body`，标题为 `h1`–`h6`，其余为 `code/quote/bulleted/numbered/todo`。
  - 文本参数栏只更新 `pendingTextKind`，参数栏按钮显示当前选中态。
  - 通用拖拽分支新增 `"文本"`：按拖拽矩形创建 `addTextBox` 或 `addCanvasTextBlock`，随后选中新文本框并切回选择工具。
  - 移除了文本工具打开时“画布按下即切换选择”的拦截，避免拖拽被吞掉。
- `Cards.kt`
  - `addCanvasTextBlock` 增加可选 `width`、`height` 参数；未传入时保持原来的 320×72（标题）/260×120（其他）。

## 4. 验证

- `text-3.png`：点击 T 后在画布空白区域拖拽，生成与拖拽区域一致的文本框，自动选中并回到选择工具；参数栏关闭。
- `text-first.png`：第一次点击 T 就显示文本参数栏，不再需要第二次点击。
- 参数栏按钮已不再产生固定位置文本。

## 5. 限制

- 文本工具需要拖拽创建；单击画布不会生成默认文本框。
- 最小尺寸 120×56，小于该区域的拖拽按最小尺寸创建。
- 创建后不会自动进入文字编辑，需要双击文本框进入编辑。
