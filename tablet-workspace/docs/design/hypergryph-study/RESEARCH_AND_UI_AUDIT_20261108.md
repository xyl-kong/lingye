## 1. 代表案例（11 项）

每项按「场景；构图与层级；文字/密度；网格/留白；色/材质/装饰；组件/反馈；运动；迁移边界」记录。`[I]` 后的句子均为针对灵页的解释。

### C01 《明日方舟》官网主导航与首页（平面/导航）

来源：[官网首页](https://ak.hypergryph.com/) `[O]`；[独立 CSS 研究](https://ak-ui.yyj.moe/en/guide/official-site-study) `[D]`。场景为访客在 INDEX、INFORMATION、OPERATOR、WORLD、MEDIA 间定位。`[O]` 首页以大幅主视觉承载品牌，导航用中英文双层标签及真实章节计数 `00 / 05`；信息按主标题、次级说明、动作入口组织。`[D]` 网页研究记录了压缩西文字体与中文无衬线的组合，以及桌面/竖屏的两种位置排布；这只是网站样本。主图形成非对称重心，导航槽和留白维持可扫描性；高对比底色及少量高亮是状态定位，不需仿制大型背景图。按钮的 hover 前后景成对改变 `[D]`；点击反馈、确切动画时长和缓动未实测。`[I]` 可借用**主任务优先 + 真正有意义的章节位置**；不迁移满屏海报、重复英文标题、持续加载装饰。

### C02 《明日方舟》情报列表（信息层级/列表）

来源：[官网情报入口](https://ak.hypergryph.com/) `[O]`；[独立页面研究](https://ak-ui.yyj.moe/en/guide/official-site-study) `[D]`。场景为浏览公告/活动/新闻。`[O]` 类别、日期、标题是不同信息位，最新消息和分类筛选分层；`[D]` 细分隔线和日期在桌面、竖屏的移位有助扫读。字重/字号的具体数值只在第三方对网页 CSS 的快照中出现，不作为游戏或本应用标准。行与行之间以节奏化空隙和细线保持密度；高亮色用于类别/动作。分类导航、新闻行与“更多”入口各有一项任务。网页 hover 仅用于鼠标，触控要有按下/选中/焦点三个独立状态。`[D]` 该研究记录“更多”链接颜色过渡 CSS 为 `.3s`，只证明样式声明，不证明实际播放帧率或缓动。`[I]` 迁移到全部文档的**类型、修改时间、标题分槽**；不迁移新闻列表的宣传性大字距。

### C03 《明日方舟》干员档案（卡片/属性）

来源：[官网干员区](https://ak.hypergryph.com/) `[O]`。场景为从角色列表进入凯尔希等档案。主角色图与文字不等权，姓名、所属、配音、介绍逐层排列；次级缩略头像形成选择路径。文字采用短标签加长正文，正文密度高于标签；具体字体和尺寸未公开。图像大面积留白与文字列形成视觉平衡；黑白信息层与少量信号色区分主次。选择角色后内容整体替换，但确切转场曲线/时长未实测。`[I]` 可将“标题—属性—正文”清楚分级用于文档属性面板；不将角色海报比例放入编辑器。

### C04 《明日方舟》世界观内容索引（目录/渐进信息）

来源：[官网 WORLD 区](https://ak.hypergryph.com/) `[O]`；[独立页面研究](https://ak-ui.yyj.moe/en/guide/official-site-study) `[D]`。场景是从主题词进入详情。`[O]` 中文主题、英文说明与返回入口共存；章节标记对应真实位置。`[D]` 研究观察到强中文标题、较弱英文描述、水平规则和侧边计数。索引不是把所有正文一次性塞满，而是先给方向；色彩与纹理服务于世界观，几何细节也标示区块。切换反馈的精确数值未测。`[I]` 可迁移**先摘要、后详情**到设置分组/模板目录；不要给每个按钮都加无语义编号。

### C05 《终末地》官网干员目录（模块/选择）

来源：[官网 Operators](https://endfield.gryphline.com/en-us) `[O]`。场景为浏览 35 位干员。`[O]` `01/35` 是数据真实进度；名称、势力、种族、引语、长描述层级明确。大图和紧凑属性列是有主次的非对称构图；属性标签短、正文可读，数字不是装饰。暗/亮分区与少量强调为视线导航。切换选择具体动效未测。`[I]` 可将页数/对象数用于真实集合浏览，但白板和文档操作区不应被角色页的大幅图像吞没。

### C06 《终末地》官网工厂介绍与日程模块（模块网格）

来源：[官网 Gameplay/AIC Factory Intro/Version Calendar](https://endfield.gryphline.com/en-us) `[O]`。场景是按主题进入玩法介绍和版本日程；官网把导航、介绍、日历及消息设为有明确名称的模块，部分介绍以 `1/5` 等真实序列提示位置。图文密度随模块职责变化，留白让每个模块的入口明确；可见元素不是统一尺寸的卡片墙。交互为进入模块/逐项浏览，网页真实过渡值未测。`[I]` 用于模板库：按任务分组与预览层级，避免等权 68 张缩略图抢注意；不复制宣传页滚动特效。

### C07 《终末地》AIC 连接反馈（交互/因果）

来源：[官方开发通讯 2026-01-17](https://endfield.gryphline.com/en-us/news/4499) `[O]`。场景是建造传送带与管线。官方明确改进引导提示，**用视觉反馈说明是否正确连接设施**，并改善移动端俯视操作及批量管线操作；未公开动画时长/缓动。这里的状态是“已连接/未连接/不可连接”，比纯粹装饰光效有更高优先级。`[I]` 灵页连线端口应在拖拽时显示可绑定范围、吸附成功/失败及最终绑定状态；现有持续流光只能作可关闭的次要反馈，不能承担唯一状态信息。

### C08 《终末地》重叠目标选择与蓝图连接保持（触控/模型一致性）

来源：[官方开发通讯 2026-07-11](https://endfield.gryphline.com/en-us/news/7017) `[O]`。场景为俯视图中点到多个重叠设施、批量移动/复制含连接对象。官方说明重叠时弹出选项列表，蓝图/批量移动复制保持连接状态，生产链可缩放浏览；管线未充满时以从起点到终点的实时流动位置表示真实输送进度。列表位置靠近歧义点，焦点转向明确对象；实际弹出动效时长/缓动未公开。`[I]` 灵页白板的跨类型重叠对象可借用“候选对象列表”，可见类型/层级/名称，选中后工具栏稳定；组合复制/模板恢复需保持连接关系。无真实流量数据的普通连线不能把流光包装成进度。不可直接照搬游戏的世界地图尺度。

### C09 《终末地》错误原因与红点降噪（反馈/信息密度）

来源：[官方开发通讯 2026-03-02](https://endfield.gryphline.com/en-us/news/2662) `[O]`。场景是设施无法放置和任务提醒。官方增加具体原因文本、优化标记与俯视选择操作；反馈的内容决定用户下一步，而不只是闪烁。颜色、标签与说明必须一致；具体字号/运动未公开。`[I]` 灵页的不可连接、锁定对象、导入失败应说明原因和可恢复动作；工具栏不要靠红点/闪光重复提醒。

### C10 《终末地》地图工具/数据终端（工具型页面）

来源：[官方 Game Tools Guide](https://endfield.gryphline.com/en-us/news/0755) `[O]`。场景是搜寻资源、筛选、定位和查阅个人实时数据。功能以搜索→筛选→定位闭环组织，而非以品牌装饰为入口；数据区需要高密度但可检索的层级。具体组件样式及动画在文字指南里没有可靠测量，记为未实测。`[I]` 这是最接近生产力应用的功能逻辑：模板、全部文档、数据库视图需先让搜索/筛选清楚，再增加辨识度。

### C11 鹰角招聘官网（品牌/真实任务）

来源：[鹰角网络招聘官网](https://career.hypergryph.com/) `[O]`。场景为求职者按美术、策划、程序等类别浏览职位并搜索关键词。`[O]` 大型双语 `JOIN US / 成为新干员` 负责品牌引导，职位类别和数量成为信息索引；招聘动态以日期、标题、摘要、阅读入口分槽。页面在品牌大标题与可检索列表之间切换密度，说明品牌表达与实际任务可以分层；具体网格单位、字号、色值及转场时长未测。按钮/筛选需要支持点击、选中和结果反馈，网页悬停不能直接替代平板按下。`[I]` 灵页可把少量品牌感放在空状态/模板库标题，文档正文和工具面板优先任务效率；不复制大号英文标语、加载百分比或海报效果。[鹰角公司主站](https://www.hypergryph.com/)本轮可解析内容不足，故没有据此编造网页视觉参数。

补充交叉印证：Hypergryph 团队在 [4Gamer 邮件访谈](https://www.4gamer.net/games/622/G062211/20231207043/) 中表示《终末地》希望延续《明日方舟》UI 设计并使其更清晰、新鲜。这是**开发团队陈述经媒体刊载**，不是像素级设计规范。

## 2. 提炼：原则而非外观

| 维度 | 可迁移的功能原则 `[I]` | 只适合品牌/游戏氛围的部分 |
|---|---|---|
| 构图 | 主任务区占优，辅助信息靠侧栏/浮层；非对称必须以任务权重平衡 | 为“工业感”偏移所有按钮、牺牲可预测位置 |
| 网格 | 4/8dp 基础节奏 + 文档内容栏/侧栏/工具层三个层级；分隔线只标记真实分组 | 到处加线、切角和小号坐标 |
| 排版 | 主语言优先；标题、内容、说明、元数据有稳定字重/明度；高密度区可扫描 | 全大写英文和极窄字体进入中文正文 |
| 色彩 | 大面积中性色，小面积语义色；选中、危险、成功各有语义 | 官网高饱和青色或游戏黄黑直接铺满编辑器 |
| 图标 | 一项动作一个符号；图标与文字一起标识关键状态 | 无语义三角、斜杠与装饰编号 |
| 组件 | 前后景成对反馈；面板有固定锚点、边界、关闭方式 | 仅依赖鼠标悬停的入口 |
| Motion | 操作结果/空间关系可见；状态变化只动必要属性 | 全局弹跳、闪烁、持续转场、线条流光当作连接证据 |

### 组件/状态规则草案 `[I]`

1. **按钮**：主操作实底、次操作轻底、文字操作无底；正常/按下/焦点/选中/禁用各自可辨。选中不能只靠颜色，另有形状/描边/位置指示。
2. **导航和工具栏**：同层入口同高度；当前页面使用稳定的底色或侧标，工具激活使用明确的图标/文字对比。工具二级菜单锚定触发控件并避开画布选中对象。
3. **卡片/面板**：内容卡片以标题、预览、元数据三层组织；属性浮层附着在对象但不遮挡操纵柄；模态设置保持“左分类/右内容”的已有效结构。
4. **表单**：开关适合二值立即生效，分段适合少量互斥，长选项用下拉；滑块必须有数值与键盘/无障碍替代。错误消息说明原因、影响、恢复办法。
5. **动效**：按下反馈与选中态分离；面板由触发点展开/收起；模式切换保持视图连续。建议试验按下 60–100ms、选择 120–180ms、面板 180–240ms，减弱运动模式改为即时状态/淡入；这些是**本应用待设备测试的提案值**，非鹰角实测。

## 4. 三套渐进方案

对照稿在 [comparison.html](./comparison.html)：同一示例内容可切换「文档/白板/设置」与 A/B/C 三案。画面为**设计示意**，不是应用截图，也不代表已实施。

| 方案 | 代表性界面变化 | 组件与 Motion | 估算工作量* | 风险 |
|---|---|---|---|---|
| A 轻量优化 | 文档保留现有三栏关系；白板保留底部工具条；设置保留左分类右内容。收齐 4/8dp 节奏、标题/说明层级和对比度。 | 现有圆角和图标；清理重复选中缩放；修补实际触控区。 | 约 4–7 人日 | 低：回归范围主要在颜色、字号、布局断点 |
| B 现代工业风融合（建议方向） | 仍是浅色编辑器，但侧栏更稳定、内容区以真实任务分组；白板工具与对象属性分层；设置组有清楚的编号/标题，仅给真实步骤编号。 | 局部细线、少量主色、轻量几何边界；状态反馈优先于装饰动效。 | 约 9–16 人日 | 中：公共 token 与多个页面适配，需防止高密度/触控冲突 |
| C 高辨识度探索 | 深石墨外壳与亮中性工作区对照；更强的模块边界、信息标签；文档仍白底，画布仍安静。 | 强品牌标题/焦点条；动效强调模式/空间转移，不加常驻闪烁。 | 约 18–30 人日 | 高：暗亮切换、对比度与性能成本；本轮只做设计，不实施 |

\* 工作量是按已有 Compose 页面/公共组件的粗估，非排期承诺，需开发勘测后校准。A 是可逆的基础；B 可在 A 验收后试点一个文档和一个白板场景；C 需要单独用户确认。

## 5. 设计令牌与组件规范草案（等待真机标定）

| 角色 | 当前或建议值 | 用途与约束 |
|---|---|---|
| `Ink` | 当前浅色 `#242424` | 主要标题/正文；保留 |
| `Muted` | 当前 `#777777` → 建议 `#525252`（浅色） | 12–14sp 说明文字；先检验实际背景，避免透明度再次压低对比 |
| `AccentText` | 建议 `#1F6CC5`（浅色白底约 5.24:1） | 小号可点击文字、选中标签；不替换所有强调背景 |
| `AccentIcon` | 当前 `#4F91E8` 可作为非文本强调候选 | 若图标承担唯一状态，须核验 3:1 非文本对比与形状辅助 |
| `SelectionFill` | 当前 `PrimarySoft=#EAF3FF` | 选中区域底色，与文本角色分开 |
| `SurfaceFloat` | 当前 `SurfaceHigh` 的语义别名 | 菜单/浮层/对话框背景，和页面背景用描边或适度阴影区分 |
| `FocusRing` | 建议由 AccentText 派生且可见 | 键盘、鼠标和无障碍焦点，不等同选中态 |
| `Danger`/`Success` | 延用现有语义角色并逐底色测对比 | 提示与操作必须配文字和图标 |

排版提案：页面标题 24–28sp/粗，区域标题 18–20sp/半粗，列表标题/控件值 14–16sp，正文 16sp，辅助信息 12–13sp（不因模仿网站缩成 9–10sp）；支持系统 200% 字体，不截断关键操作。间距采用 4dp 基数，内容区内距 24–32dp、组间 24–32dp、同行相关项 8–12dp，具体须在 360/520/640/平板宽屏截图复核。按钮/行的**实际触控热区**目标 ≥48×48dp；图标画面可小于热区。[Android 官方](https://developer.android.com/guide/topics/ui/accessibility/apps.html)建议小于 18sp 的普通文字对比度至少 4.5:1，触控区至少 48×48dp。色弱/黑白模式与深色模式仍要能区分选中、错误、连接。

组件提案：导航行 48–52dp；图标本体 18–20dp；主按钮 48dp 高；分段控件每段可点区域 ≥48dp 高；菜单行 48–56dp，危险操作位置/颜色/文本一致；浮动工具条内 icon 视觉可沿用 18–20dp，点击区域单独扩至 48dp；设置行标题/说明左列、控件右列共用基线；弹窗背景用 `SurfaceFloat`，边界通过 1dp 线/轻阴影清晰定位。以上为**候选参数**，不是马上全量覆盖源码的指令。

Motion 提案：动作按下有即时明度反馈；选择改变稳态标记；展开从锚点附近出现；关闭回到锚点；白板连线流光默认不作为连通状态、可关闭并遵守减少动画。避免同时对同一选中事件驱动颜色、位移、缩放和阴影。用 60fps 录屏检查不跳变、不遮挡、不影响笔输入。

## 7. 分阶段实施与验收（获确认后）

1. **基线采集**：在当前 APK/模拟器与至少一台安卓平板上截图主界面、全部文档列表/卡片、模板、Journal、文档空/密、白板空/多对象、设置各类别、弹窗与菜单；记录分辨率、系统字号、深浅色。与本报告旧图分开归档。
2. **A 样板**：只做颜色语义拆分、文字层级/实际触控区/选中动效样板；检测 4.5:1/3:1、48dp、200% 字体、360/520/640dp、键盘焦点。原生组件状态不回归。
3. **B 试点**：文档、白板、设置各一个完整任务流：创建→编辑→打开浮层→保存/关闭；重叠对象候选、端口状态、模板列表另作专项。录屏检查状态因果与 60fps 丢帧。
4. **C 单独评审**：仅在 A/B 验收和用户确认后探索强品牌壳层；比较盲测任务时间、误触、可读性与主观辨识度，不以“更像游戏”作为成功标准。
5. **统一回归**：原功能、备份恢复、深浅主题、重启保留、手写/手掌误触、平板横竖屏/分屏、外接鼠标/键盘；旧审计的 `UNVERIFIED` 不因设计稿而自动变 `VERIFIED`。

验收建议：① 主要任务完成率/耗时不劣于当前基线；② 小号文字和功能性图标满足相应对比；③ 关键控件实际 hit bounds ≥48dp 且邻项不冲突；④ 选中/禁用/错误可在灰度下分辨；⑤ 文档与白板 200% 字体、深浅主题、触笔操作无裁切或阻塞；⑥ 设计稿、模拟器图与真机图分别标注版本和时间。
