## 1. 研究依据与产品边界

沿用[首轮 11 项案例研究](./RESEARCH_AND_UI_AUDIT_20261108.md)，并增加[9 项官方来源的深入交互证据](./DEEP_SOURCE_NOTES_20261108.md)。案例包含[《明日方舟》官网](https://ak.hypergryph.com/)的新闻/角色信息层级、[《终末地》官网](https://endfield.gryphline.com/en-us)的模块与数据目录、[官方 AIC 连接反馈说明](https://endfield.gryphline.com/en-us/news/4499)、[官方重叠对象和管线状态说明](https://endfield.gryphline.com/en-us/news/7017)、[鹰角招聘官网](https://career.hypergryph.com/)的品牌标题与任务列表分层。独立 [AK/UI 网站研究](https://ak-ui.yyj.moe/en/guide/official-site-study)是第三方观察，不是官方规范。工业主题取**构图、层级、状态因果**，不复制商标、图形、字体文件或游戏资产。

**三个不变量**：① UI 主题只作用于应用 chrome，不改用户创建的文档/白板对象属性；② Default Monochrome 第一次引入主题系统时像素/交互等效；③ 一次切换是整个应用的一次状态提交，不能有页面先后变色。

### 2.1 硬编码样式优先盘点

- `VisualDesign.kt` 中 `LingyeColors` 约数十个浅/深颜色配对，是最可靠的迁移入口；`LingyeTheme` 已将其中一部分传给 Material3。必须保留其 Default 数值，不能把“工业主题设计稿”直接覆盖原令牌。
- `MainActivity.kt` 侧栏 250dp、38dp 图标动作、动画 150/220/260ms，以及各页面 `RoundedCornerShape(6–20.dp)` 属于布局/形状/时间硬编码。不要机械全量替换：触控和位置是行为契约，纯视觉半径可逐类迁移。
- `AllDocumentsHome.kt` 的滑动操作含固定绿/蓝/黄/红值；这是语义动作色，需映射 `success/info/warning/danger`，并保持动作含义。`SettingsPage.kt` 分段 220ms、圆角 15/18dp；`CanvasRendering.kt` 选中手柄、吸附线、框选蓝、网格点和装饰绘制有直写值，需要区分 chrome 与内容。
- 模板图片、用户插入图片、已存文档/白板颜色和字体，属于内容/资源，**不是主题适配对象**。工业主题可以改变预览容器，不能重绘内容。

### 2.2 能力结论

现有基础足以做最小侵入式主题系统：Compose 重组 + 已有 `LingyeColors`/Material3 + `WorkspaceSettings` 持久化。但尚无主题 ID、字体/形状/motion 语义令牌和完整组件变体，且自绘画布 chrome、部分菜单及页面硬编码不能自动随 MaterialTheme 变化。**现状不具备“一键全应用一致切换”能力**。先建注册表和解析层，再按组件表逐步适配；不得在只读审计后直接替换全局颜色。

## 3. 主题架构设计（拟议，不是已实现）

```text
WorkspaceSettings.uiThemeId ─┐
WorkspaceSettings.themeMode ──┼─> ThemeResolver ─> ResolvedUiAppearance
系统深浅/减少动效 ───────────┤                     ├─> Material3 ColorScheme/Typography/Shapes
可选 UI 配色覆盖 ─────────────┘                     ├─> LingyeColors 兼容层
                                                   └─> 现有公共组件/画布 chrome
页面数据、画布对象样式 ────────────────────────────────> 原编辑器/渲染器（不经 UI theme）
```

`ThemeDefinition(id, version, light, dark, typography, shapes, components, icons, motion, decoration)` 为不可变配置，注册表初期仅内置两套。`ThemeResolver` 一次性解析主题 ID、明暗、允许覆盖的 UI 配色和系统减少动效，产生同一 `ResolvedUiAppearance` 快照；根 CompositionLocal 提供给所有页面。`MaterialTheme` 仅是其中一个消费者，自绘/旧组件也读同一快照。未来增加主题只需增加定义并完成组件适配矩阵，不允许 `if (themeId == industrial)` 散落业务页面。

**存储与异常**：新 key `ui_theme_id`，缺失/未知/损坏时只回退至 Default，不重置 `theme_mode` 或用户内容；读写沿用 `WorkspacePreferenceStore`，启动前读取主题 ID + 明暗，避免启动闪屏。切换时先校验完整配置，原子替换根 appearance，再异步持久化；写入失败显示错误并恢复原选择。主题资源采用内置矢量/纯绘制，缺图标回退现有 `AppIcon`。恢复默认仅改 UI theme ID，不清除自定义画布色。

**优先级**：主题预设给 UI 视觉语言；主题允许的*UI 强调色覆盖*（当前应用尚无独立 UI 覆盖字段，需先设计其范围）只影响交互强调，不能覆盖 warning/error/success 或令对比不足；`themeMode` 决定该主题的浅/深变体；文档样式与白板对象数据独立。现有设置的“画布背景/笔记颜色/连线颜色”等是内容默认值，不应当当作 UI accent。

**模块边界**：页面调用 `Appearance.current` 取 token，而不是拥有主题逻辑；图标、菜单、按钮复用原 API；`Page`、Repository、画布对象序列化、撤销栈与事件系统不改。若组件外形需要切角，以 `Shape` 绘制替代额外嵌套 hitbox，先确认布局测量不变。

## 4. 阶段 B：双主题规范

### 4.1 Theme 01 / Default Monochrome

基准为**当前代码实际观感**，含 light/dark 与已有黑白控件。`LingyeColors` 当前值原样映射，举例：浅色 `Ink #242424`、`Muted #777777`、`Primary #4F91E8`、`Background #FFFFFF`、`Sidebar #FAFAFA`、`Line #E5E5E5`；开关黑底、分段黑色选中、既有菜单圆角与阴影保持。这一主题的第一目标是**无差异迁移**：旧数据/旧偏好读入后截图和交互等效。此前研究指出的对比度问题应另列无障碍改进任务，不能借主题架构改造时悄悄改 Default。

### 4.2 Theme 02 / Industrial Terminal（V1 色板记录，已被 V5 评审稿取代）

概念：**一台安静、精密的创作工作台**。关键词：信息槽、对齐、工艺线、状态点、局部青蓝信号、纸面内容。原创性边界：无《明日方舟》专有符号/Logo/字库/素材；不把刀切角、英文编号当作统一答案。大面积中性表面（约 80–90% 视觉面积），功能性强调色用于当前操作与连线绑定；正文和画布仍优先可读。

表中为**候选色值**，不是已测通过的色板；每个 on-color、状态、透明度与背景组合都要在 Android 实际渲染中验证。工业主题强调色不是官网蓝/游戏黄的复制。深色和浅色是**同一视觉语言的两种光照**，不是第三套主题。

**Typography**：UI 中文优先采用系统无衬线；标题 24/20/16sp 三层（700/600/600），正文控件 14–16sp（400/500），辅助 12–13sp（500），真实编号/计量可用系统等宽 11–12sp；中文正文不加大字距，短英文状态标签最多 +0.04em。正文行高约 1.45–1.6，说明行高约 1.35。Default 保留原各页面字号，工业配置先作用 UI chrome；已有文档字体、字号、格式和代码块字体原样保留。字号仍遵循系统缩放和用户编辑器字体偏好。

**Geometry**：4dp 基础间距；界面模块用稳定的左对齐轴与细线，侧栏 250dp 基准不变；主操作 8dp 圆角、次级面板 6dp、浮层 10dp。只在浮层标头或状态标签采用**单角小切角**（例如 6dp），避免作用于密集按钮/输入框。边框 1dp，焦点描边 2dp；阴影仅区分真实层级。装饰线和编号永远 `pointerInput` 透明，剪裁不改变 48dp 触控区域。

**Icon**：复用 `AppIcon/WorkspaceIcon` 功能映射；工业主题可把图标线宽统一为约 1.8dp、局部用方形浅底承托，保持 18–20dp 视觉尺寸与 48dp 点击区。缺少特化图标时使用 Default 路径，不留空。内容对象图标（用户插入图）不替换。

**Motion**：基于功能而不是气氛。建议按下 60–90ms、选中 120–160ms、面板进/出 180/140ms、导航 160–200ms；以 ease-out 进入、ease-in 退出，避免 spring 弹跳、反复脉冲和闪烁。数值为本主题提案，不是鹰角官方测量。系统动画关闭时立即转至最终状态；减少动效时保留颜色/描边反馈，取消空间位移和持续流光。白板线条的可选光点动效只表“连通视觉提示”，**不能虚构数据流进度**，且必须可关闭。

**装饰**：局部模块标题可有真实索引（如当前页 02/12），空状态用低对比细格，不放入正文或画布中心；背景图案在工具层背后、对比低、禁用点按。只有会帮助辨别层级/状态的线与标记进入组件。大型海报、伪终端日志和无意义坐标不用。

### 4.3 组件状态矩阵（工业主题）

| 组件族 | 正常 | hover/按下 | 选中/开启 | 禁用/错误/焦点 |
|---|---|---|---|---|
| Button、Tabs、Sidebar、Toolbar | 中性表面+清晰标签 | 前后景联动，按下不位移布局 | 浅青底+侧标/下划线，图标与字同语义 | 降对比但可辨；焦点 2dp 外环 |
| Toggle、Checkbox、Slider、Segmented | 轮廓/轨道清楚，值有文本 | 控件内部明度变化 | 强调色轨道/勾/指示块，不只靠颜色 | 禁用阻断操作；错误含原因说明 |
| Dropdown、Input、搜索 | 1dp 边界+占位/值分级 | 按下边界加强 | 展开箭头/活动边界对应浮层 | 校验错误写明问题；键盘焦点可见 |
| Card、Dialog、Popover、Tooltip | 卡片无多余阴影；浮层真实抬升 | 可操作卡片才有 hover | 已选卡片有标记/描边 | modal 有遮罩/关闭；tooltip 不挡操作 |
| Context Menu、Floating Panel、Scrollbar | 锚点、容器、分区稳定 | 菜单项整行响应 | 当前工具和属性状态明确 | 危险动作文字+色；边缘翻转不盖手柄 |
| Toast、Loading、Progress、Empty | 文本明确下一步 | — | 进度表示真实任务 | 错误可恢复；减少动效停掉循环装饰 |

默认主题状态矩阵以当前 `MenuRow`、`CompactSwitch`、`ModeSwitcherButton`、`Settings*` 等既有外观和行为作为快照；在主题切换基础设施通过回归后才考虑单独的无障碍修正。

## 6. 阶段 C–E 的实施顺序与质量门禁（待确认后）

1. **C0 冻结 Default 基线**：记录当前提交/工作树、两种明暗和 5 个代表页面截图、组件状态、持久化样本。当前未提交代码需先厘清归属，不能覆盖。
2. **C1 主题定义/解析/存储**：注册表 + 不可变解析结果 + `ui_theme_id` + 启动读取/安全回退。最先做到两主题切换但仅一个样板组件变化，Default 截图必须等效。
3. **C2 公共组件**：色/字/形/motion/icon 逐族接入。维护“组件 × 两主题 × 明暗 × 状态”覆盖表；只在所有依赖已接入后开放主题入口，避免半主题发布。
4. **D 页面适配**：壳层→全部文档/模板/Journal→设置→编辑器 chrome→画布 chrome→反馈浮层。每批验证导航、菜单锚点、触控区域和存储不变量；不换引擎/编辑器。
5. **E 统一验收**：冷启动/切换/重启/未知 ID 回退；默认主题视觉对照；工业主题各页和组件状态；文档与画布内容切前切后像素/序列化值不变；深浅、360/520/640/平板、200% 字体、触笔、鼠标键盘；性能看切换帧和画布绘制。合格前不称“全应用主题完成”。

验收底线参考 [Android 官方无障碍建议](https://developer.android.com/guide/topics/ui/accessibility/apps.html)：小号普通文本 ≥4.5:1、关键非文本状态 ≥3:1、实际触控目标 ≥48×48dp；不能以装饰线、颜色或动效作为唯一状态表达。

## 7. 需确认后才能实施的决策

当前等待用户评审 [V5 页面预览](./endfield-theme-v5.html) 的组件造型、层级与交互方式。V1 的青蓝方案已停用；V5 采用暖白工作台、深色选中面和少量信号黄，并严格保持原布局和白板内容。若方向通过，再为深色变体、完整组件矩阵和实际 Android 触控尺寸做下一轮设计。此阶段没有修改或推送应用代码。
